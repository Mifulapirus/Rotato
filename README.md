## 1. Project Overview

**Rotato** is a small combat-style workshop robot built at Asmbly. Students assemble the hardware and then customize the firmware.

| Item | Detail |
|---|---|
| Microcontroller | ESP32-C3 Super Mini |
| Firmware framework | Arduino (via PlatformIO) |
| Language | C++ |
| Build system | PlatformIO (`platformio.ini`) |
| Web server | ESPAsyncWebServer (non-blocking) |
| BLE stack | NimBLE-Arduino |
| JSON | ArduinoJson v7 |
| Filesystem | LittleFS (stores the web UI HTML) |

The robot is controlled through a **browser-based web UI** served directly by the robot over WiFi, and optionally through a **Bluetooth Low Energy (BLE)** Android app.

## 3. Hardware — Electronics Connections

### 3.1 Microcontroller: ESP32-C3 Super Mini

All GPIO numbers below are the logical ESP32-C3 GPIO numbers (same as the numbers in `config.h`).

| GPIO | Connector | Signal | Notes |
|------|-----------|--------|-------|
| GPIO0 | — | Battery ADC | Voltage divider: R1=20KΩ, R2=10KΩ. Reads 2S LiPo (7.4V nominal). |
| GPIO1 | J5 | Left wheel ESC signal | RC PWM 50Hz, 1000–2000 µs |
| GPIO3 | J6 | Right wheel ESC signal | RC PWM 50Hz, 1000–2000 µs |
| GPIO4 | J7 | Weapon motor ESC signal | RC PWM 50Hz, 1000–2000 µs |
| GPIO5 | J8 | Safety switch | Active LOW, INPUT_PULLUP. Short to GND = weapon blocked. |
| GPIO6 | J9 | Expansion (unused) | Free for student projects |
| GPIO7 | — | Buzzer (via JP1) | Passive buzzer. JP1 solder jumper must be closed to connect. If JP1 is open, GPIO7 is free. |
| GPIO9 | — | BOOT button (built-in) | Active LOW. Hold 3 seconds to clear saved WiFi credentials + reboot. |

### 3.2 Battery Circuit

```
Battery (+) ── R1 (20KΩ) ── GPIO0 ── R2 (10KΩ) ── GND
```

- Battery type: 2S LiPo
- Voltage range: 6.0V (0%, minimum safe) – 8.4V (100%, fully charged)
- The divider brings ~8.4V down to ~2.8V, safe for the ESP32-C3 ADC (max 3.3V)
- `BATTERY_R_RATIO` in `config.h` is the multiplier to recover battery voltage from the ADC reading (default: 3.64)

### 3.3 Motor Connectors (ESC PWM Output)

Standard RC servo/ESC signal: **50 Hz, 1000–2000 µs pulse width**

| Pulse width | Meaning |
|-------------|---------|
| 1000 µs | Full reverse (drive) / ESC disarmed (weapon) |
| 1500 µs | Neutral / stop |
| 2000 µs | Full forward / full speed |

- The ESP32 LEDC peripheral generates these pulses in hardware.
- **Left motor (J5)**: LEDC channel 0, GPIO1. Set `MOTOR_LEFT_REVERSED = true` in `config.h` if it spins the wrong way.
- **Right motor (J6)**: LEDC channel 1, GPIO3. Set `MOTOR_RIGHT_REVERSED = true` in `config.h` if it spins the wrong way. (Default: reversed = true, because one motor is mounted mirrored.)
- **Weapon motor (J7)**: LEDC channel 2, GPIO4. Weapon ESCs require a 2-second initialization hold at 1000 µs before they will accept commands.

### 3.4 Buzzer (JP1 / GPIO7)

- **Passive buzzer** — requires a PWM signal at the desired pitch frequency (not just DC).
- Connected through solder jumper **JP1**. If JP1 is not soldered closed, the buzzer does nothing and GPIO7 is free.
- Controlled by `BuzzerController`, which is **non-blocking** (uses `millis()`, not `delay()`).
- Feature flag: `#define HAS_BUZZER` in `config.h`. Comment it out if no buzzer is connected.

### 3.5 Safety Switch (J8 / GPIO5)

- A physical switch wired between GPIO5 and GND.
- When the switch is **open** (not pressed): GPIO5 is HIGH (pulled up) → weapon **allowed**.
- When the switch is **closed** (pressed/shorted): GPIO5 is LOW → weapon **blocked**.
- Firmware checks this every loop iteration. If the weapon is already running when the switch is triggered, it stops immediately.
- Feature flag: `#define HAS_SAFETY_SWITCH` in `config.h`.

## 4. Firmware Architecture

### 4.1 Module Overview

```
main.cpp
  │
  ├── hardware/MotorController    — Drive arcade mixing + weapon PWM + ESC arming
  ├── hardware/BuzzerController   — Non-blocking beep sequences
  ├── hardware/BatteryMonitor     — Rolling-average ADC + voltage-to-percent
  ├── hardware/SafetySwitch       — Debounced digital input
  │
  ├── connectivity/WiFiManager    — AP or STA mode, NVS credential storage
  ├── connectivity/WebServerManager — ESPAsyncWebServer + WebSocket JSON protocol
  └── connectivity/BLEManager    — NimBLE GATT server for Android app
```

`main.cpp` creates one instance of each class, wires callbacks from the connectivity layer into the hardware layer in `setup()`, then calls `update()` methods in `loop()`.

### 4.2 Startup Sequence

1. Serial (USB-CDC, 115200 baud) — logs firmware version and chip info
2. Hardware drivers initialized — motors set to neutral, battery read, buzzer/safety configured
3. WiFi — tries saved STA credentials; falls back to AP mode
4. Web server + WebSocket started
5. BLE GATT server started
6. Startup beep plays; robot prints its IP to Serial

### 4.3 Main Loop

- **Safety switch** checked every iteration; weapon stopped immediately if triggered
- **ESC arming timer** advanced every iteration (2-second power-on hold)
- **Battery ADC** sampled every 500ms
- **WebSocket status broadcast** sent to browser every 500ms
- **BLE status notify** sent to Android app every 500ms
- **Buzzer** stepped forward (non-blocking sequence engine)
- **WebSocket cleanup** (async library housekeeping)
- **Boot button** polled — hold 3 seconds clears WiFi credentials and reboots

### 4.4 Drive Mixing (Arcade Drive)

The joystick sends X (turn) and Y (throttle) values in range –1.0 to +1.0.
The firmware mixes them into left/right wheel speeds:

```
leftSpeed  = Y + X   (clamped to −1.0 … +1.0)
rightSpeed = Y − X   (clamped to −1.0 … +1.0)
```

These are then mapped to PWM pulse widths:
```
pulse_us = 1500 + speed × halfRange
```
where `halfRange` defaults to 500 µs (giving the standard 1000–2000 µs window).

### 4.5 Weapon ESC Arming

RC ESCs require the control signal to sit at minimum throttle (1000 µs) at power-on for at least 2 seconds before they will respond to commands. The firmware enforces this:

1. On boot, weapon PWM is set to 1000 µs.
2. `MotorController::updateEscState()` is called every loop to count down the 2-second delay.
3. Until `isEscReady()` returns `true`, the web UI weapon button is disabled.

**ESC full-range calibration** (teaches the ESC the signal endpoints):
1. Sends max throttle (2000 µs) for 3 seconds — ESC should beep.
2. Sends min throttle (1000 µs) for 3 seconds — ESC should beep again.
3. Triggered from the web UI settings panel. **Disconnect the weapon motor first.**

### 4.6 NVS (Non-Volatile Storage)

Settings that survive power cycles are stored in ESP32 NVS (flash):

| Setting | Key | Default |
|---------|-----|---------|
| WiFi SSID | `ssid` | none |
| WiFi password | `pass` | none |
| Custom robot name | `name` | `Rotato-XXXX` (MAC-based) |
| AP password | `ap_pass` | `12345678` |
| Battery calibration ratio | in BatteryMonitor NVS | `3.64` |
| Weapon ramp time | in MotorController NVS | `500` ms |
| Weapon curve | in MotorController NVS | `0` (linear) |

## 5. WiFi & Web UI

### 5.1 Access Point Mode (Default)

On first boot (no saved WiFi credentials), the robot creates its own hotspot:

| Setting | Value |
|---------|-------|
| SSID | `Rotato-XXXX` (XXXX = last 4 hex chars of MAC address) |
| Password | `12345678` (WPA2 minimum 8 chars) |
| Robot IP | `192.168.4.1` |

Connect your phone or laptop to this network, then open `http://192.168.4.1` in a browser.

### 5.2 Station Mode (Optional)

Enter your home/workshop WiFi credentials in the web UI Settings panel. The robot saves them to NVS and reboots. If it can connect (10-second timeout), it joins your network and gets a DHCP IP. If it cannot connect, it falls back to AP mode automatically.

**To reset WiFi credentials:** Hold the BOOT button (GPIO9) for 3 seconds after roobot has booted.

### 5.3 WebSocket JSON Protocol

The browser communicates with the robot over WebSocket at `ws://<robot-ip>/ws`.

**Browser → Robot (commands):**

```json
{ "type": "drive",    "x": 0.5,      "y": 0.8 }
{ "type": "weapon",   "active": true }
{ "type": "weaponSpeed", "speed": 0.75 }
{ "type": "weaponAccel", "rampMs": 500, "curve": 0 }
{ "type": "settings", "ssid": "MyNetwork", "pass": "password123" }
{ "type": "forget" }
{ "type": "rename",   "name": "MyRobot" }
{ "type": "apPassword", "pass": "newpassword" }
{ "type": "pwmRange", "halfRangeUs": 500 }
{ "type": "batteryCalib", "ratio": 3.64 }
{ "type": "escCalibrate" }
{ "type": "bleEnable", "enabled": true }
```

**Robot → Browser (status, every 500ms):**

```json
{
  "battery": 85,
  "voltage": 7.8,
  "ratio": 3.64,
  "safety": true,
  "ip": "192.168.4.1",
  "weapon": false,
  "fw": "1.0.0+42",
  "name": "Rotato-A3F2",
  "escReady": true,
  "escCalib": "idle",
  "weaponSpeedPct": 0
}
```

## 6. Bluetooth Low Energy (BLE)

The robot also advertises a BLE GATT server for use with an Android app.

### 6.1 GATT Profile

| | Value |
|---|---|
| Service UUID | `a1b2c3d4-e5f6-7890-abcd-ef1234567890` |
| Advertised name | Same as WiFi SSID (`Rotato-XXXX`) |

| Characteristic | UUID | Direction | Format |
|----------------|------|-----------|--------|
| DRIVE_X | `...ef1234567891` | App → Robot | 4-byte little-endian float, −1.0 to +1.0 |
| DRIVE_Y | `...ef1234567892` | App → Robot | 4-byte little-endian float, −1.0 to +1.0 |
| WEAPON | `...ef1234567893` | App → Robot | 1-byte uint8: `0x00` = off, `0x01` = on |
| STATUS | `...ef1234567894` | Robot → App (NOTIFY) | UTF-8 JSON every 500ms |

BLE STATUS payload:
```json
{ "battery": 85, "safety": true, "weapon": false, "fw": "1.0.0+42" }
```

### 6.2 Enabling / Disabling BLE

- `#define BLE_ENABLED` in `config.h` — comment out to completely exclude BLE.
- At runtime, BLE can be toggled from the web UI without rebooting.

## 7. Configuration Reference (`src/config.h`)

`config.h` is the **single place to change hardware settings**. All other files read their values from here.

### Feature Flags

```cpp
#define HAS_BUZZER          // Remove if JP1 is not soldered
#define HAS_SAFETY_SWITCH   // Remove if no switch on J8
#define BLE_ENABLED         // Remove to exclude BLE entirely
```

### Pin Definitions

```cpp
#define PIN_BATTERY_ADC   0   // GPIO0 — voltage divider ADC
#define PIN_MOTOR_LEFT    1   // GPIO1 — J5: left ESC
#define PIN_MOTOR_RIGHT   3   // GPIO3 — J6: right ESC
#define PIN_MOTOR_WEAPON  4   // GPIO4 — J7: weapon ESC
#define PIN_SAFETY_SWITCH 5   // GPIO5 — J8: kill-switch
#define PIN_EXPANSION_1   6   // GPIO6 — J9: free expansion
#define PIN_BUZZER        7   // GPIO7 — buzzer (JP1)
#define PIN_BOOT_BUTTON   9   // GPIO9 — built-in BOOT button
```

### Motor Direction

```cpp
#define MOTOR_LEFT_REVERSED   false  // flip if left motor goes backwards
#define MOTOR_RIGHT_REVERSED  true   // flip if right motor goes backwards
```

### PWM / RC Protocol

```cpp
#define PWM_FREQUENCY_HZ    50      // 50 Hz standard RC signal
#define PWM_RESOLUTION_BITS 14      // 14-bit LEDC (ESP32-C3 max)
#define PWM_NEUTRAL_US      1500    // Stop
#define PWM_MIN_US          1000    // Full reverse
#define PWM_MAX_US          2000    // Full forward
#define PWM_DRIVE_HALF_RANGE_US 500 // ±µs from neutral (increase for wider throw)
```

### Weapon ESC Timing

```cpp
#define ESC_INIT_DELAY_MS    2000   // Boot hold at minimum (ms)
#define ESC_CALIB_HIGH_MS    3000   // Full-range calib: hold max (ms)
#define ESC_CALIB_LOW_MS     3000   // Full-range calib: hold min (ms)
#define WEAPON_RAMP_MS_DEFAULT 500  // Time to ramp 0→100% speed
#define WEAPON_CURVE_DEFAULT   0    // 0=linear, 1=quadratic, 2=s-curve
```

### WiFi

```cpp
#define AP_SSID_PREFIX    "Rotato-"     // SSID will be e.g. "Rotato-A3F2"
#define AP_PASSWORD       "12345678"    // Must be >= 8 chars (WPA2)
#define AP_IP_ADDRESS     "192.168.4.1"
#define STA_CONNECT_TIMEOUT_MS 10000   // 10s timeout for station mode
```

### Battery Monitor

```cpp
#define BATTERY_R_RATIO       3.64f  // Voltage divider multiplier
#define BATTERY_VOLTAGE_FULL  8.4f   // 2S LiPo fully charged
#define BATTERY_VOLTAGE_EMPTY 6.0f   // 2S LiPo minimum safe
#define BATTERY_NUM_SAMPLES   8      // Rolling average samples
```

## 8. Building and Flashing

### Prerequisites

- [PlatformIO](https://platformio.org/) — install as a VS Code extension or CLI
- USB-C cable connected to the ESP32-C3 Super Mini

### Build Commands

```bash
# Build firmware only
pio run

# Flash firmware to the robot
pio run --target upload

# Upload the web UI (do this before flashing firmware on first use)
pio run --target uploadfs

# Open serial monitor (115200 baud)
pio device monitor
```

> **Order matters on first flash:** Run `uploadfs` first (uploads `data/index.html` to LittleFS), then `upload` (flashes the firmware).

### Version Bumping

Edit `src/version.h` and change `MAJOR`, `MINOR`, or `PATCH`. The build number auto-increments every compile.

### Serial Debug Output

The firmware prints detailed boot info and runtime events over USB-CDC Serial at 115200 baud.
Key prefixes: `[Boot]`, `[WiFi]`, `[Web]`, `[BLE]`, `[Motor]`, `[Main]`

## 9. How to Make Common Changes

### Change the robot's WiFi name (SSID)

From the web UI: open the Settings panel → enter a name in the **Robot Name** field → Save.
In code: this sets a custom name in NVS. To revert, clear with the BOOT button (3-second hold) or click **Forget/Reset** in the web UI.

### Change the default AP password

Edit `AP_PASSWORD` in `config.h` and reflash. Or change it at runtime from the web UI Settings panel.

### Motor spins the wrong direction

Set `MOTOR_LEFT_REVERSED` or `MOTOR_RIGHT_REVERSED` to `true` in `config.h` and reflash.

### Add a new WebSocket command

1. Add a new `using XyzCallback = std::function<...>` type in `WebServerManager.h`
2. Add `void onXyz(XyzCallback cb)` method and `_xyzCallback` member
3. Parse the new `"type"` in `WebServerManager.cpp` and call the callback
4. Register the callback in `main.cpp` in `setup()`

### Add a new buzzer sequence

1. Define a `static const BeepStep mySequence[] = { ... }` array in `BuzzerController.cpp`
2. Add a `void beepMyEvent()` method that calls `playSequence(mySequence, N)`
3. Declare it in `BuzzerController.h`
4. Call `buzzer.beepMyEvent()` from `main.cpp` wherever appropriate

### Add new persistent (NVS) settings

Use the `Preferences` library. Open a namespace, `putString` / `putInt` / `putFloat` to write, `getString` / `getInt` / `getFloat` to read. See `WiFiManager.cpp` or `MotorController.cpp` for examples.

## 10. Key Design Patterns in This Codebase

| Pattern | Where used | Why |
|---------|-----------|-----|
| **Callback-based decoupling** | `WebServerManager`, `BLEManager` | Hardware layer doesn't depend on network layer; easy to test independently |
| **Non-blocking timing** | `BuzzerController`, main loop | Never use `delay()` in the main loop — it freezes WebSocket and BLE |
| **NVS for persistence** | `WiFiManager`, `MotorController`, `BatteryMonitor` | Settings survive power cycles without EEPROM |
| **Feature flags** | `HAS_BUZZER`, `HAS_SAFETY_SWITCH`, `BLE_ENABLED` | Stubs compile to nothing when the feature is disabled |
| **Single config file** | `config.h` | Students only need to edit one file for hardware changes |
| **Arcade drive mixing** | `MotorController::setDrive()` | Standard pattern for differential-drive robots |

## 11. Useful Context for AI Assistants

When asking an AI assistant for help with this codebase, include relevant sections of this document. Here are some starting prompts:

**To make a firmware change:**
> "I'm working on the Rotato robot firmware (ESP32-C3, PlatformIO/Arduino, C++). [Paste this file.] I want to [describe your change]. The relevant files are [list them]."

**To add a new feature:**
> "I want to add [feature] to this robot. The architecture uses callback-based decoupling between hardware/ and connectivity/ modules. All hardware settings are in config.h. Please follow the existing patterns."

**To debug a problem:**
> "My robot [describe behavior]. Serial output shows: [paste Serial output]. Relevant config: [paste config.h section]."

**Important things the AI should know:**
- This is Arduino-style C++, not bare ESP-IDF. Use Arduino API functions (`millis()`, `ledcSetup()`, `ledcWrite()`, `Preferences`, etc.)
- **Never use `delay()` in `loop()`** — it will freeze the WebSocket server and BLE stack
- All pin numbers are in `config.h`. Don't hardcode GPIO numbers in other files
- The web UI (`data/index.html`) communicates over WebSocket using the JSON protocol in Section 5.3
- NimBLE-Arduino v2.x API is used for BLE (not the older ESP32 BLE library) — check NimBLE docs if modifying BLE code
- `ESPAsyncWebServer` is non-blocking and event-driven — callbacks run from the network task, not the Arduino loop task. Keep them short and avoid calling `Serial.println` heavily inside them
- `ArduinoJson` v7 is used — the API changed significantly from v6. Use `JsonDocument` (not `DynamicJsonDocument`)
